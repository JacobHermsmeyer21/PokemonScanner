Act as a senior Android engineer, computer-vision engineer, and software architect. Design and implement an Android application that scans Pokémon displayed inside Pokémon GO, extracts their information, stores the results in a local database, and provides tools to search, filter, edit, export, and manage the collected records.

The application is for personal research and inventory management. Before implementing automation, clearly identify any Android, Google Play, accessibility, privacy, or Pokémon GO terms-of-service concerns. Design the project so that the core scanning and database features work without unattended game automation. Keep any automatic swipe functionality isolated behind a clearly labeled experimental/debug-only module.

## Primary goal

The app should inspect a Pokémon detail screen in Pokémon GO and collect:

- Pokémon species name
- Nickname, when present
- Combat Power, or CP
- Pokémon level
- Attack IV from 0 to 15
- Defense IV from 0 to 15
- Stamina/HP IV from 0 to 15
- Total IV percentage
- Current HP, when visible
- Form or regional form, when detectable
- Shiny status, when detectable
- Favorite status, when detectable
- Scan timestamp
- A screenshot or cropped image reference, optionally
- A confidence score for each detected field

After scanning, the app should store the result in a Room database.

The desired workflow is:

1. The user opens a Pokémon in Pokémon GO.
2. The Android app captures the screen using MediaProjection.
3. The app waits until the screen is stable.
4. It detects the Pokémon detail screen.
5. It reads the Pokémon name and CP.
6. It opens or reads the appraisal screen when available.
7. It detects the Attack, Defense, and HP IV bars.
8. It calculates the Pokémon’s level using species base stats, CP multipliers, CP, and IV values.
9. It validates the result.
10. It saves the Pokémon to the database.
11. In experimental automatic mode, it swipes to the next Pokémon.
12. It repeats until all Pokémon have been processed.
13. It stops automatically when it determines that the end has been reached or when repeated scans indicate that it is no longer advancing.

## Important design constraint

Build two operating modes.

### Mode 1: User-assisted scanning

This should be the primary and safest mode.

The user manually navigates Pokémon GO and presses a floating Scan button. The app captures, analyzes, and stores the current Pokémon. The user then manually moves to the next Pokémon.

This mode must not require an accessibility service.

### Mode 2: Experimental automatic scanning

This mode may use an Android AccessibilityService to perform gestures such as:

- Opening appraisal
- Closing appraisal
- Swiping to the next Pokémon
- Waiting for the next screen to stabilize
- Stopping when scanning is complete

Keep this feature separate from the main scanner, disabled by default, and clearly marked as experimental and potentially incompatible with Pokémon GO or Google Play policies.

Do not use network interception, game memory access, packet inspection, root access, code injection, account credentials, reverse engineering of private APIs, or modification of Pokémon GO.

The scanner must not run OCR on every frame. It should:

1. Downscale frames.
2. Compare consecutive frames.
3. Use structural similarity, perceptual hashing, or pixel-difference thresholds.
4. Process only after the screen has remained stable for a configured duration.

For OCR:

- Normalize contrast.
- Remove unnecessary background areas.
- Support common OCR mistakes.
- Use Pokémon-name fuzzy matching against a local species list.
- Return confidence values.
- Preserve the original OCR result for debugging.

For IV-bar detection:

- Crop each bar.
- Detect the filled portion.
- Map the fill length to an integer from 0 to 15.
- Account for anti-aliasing, animation, scaling, and partial segments.
- Validate detected values against the appraisal badge or IV percentage where possible.

## Pokémon level calculation

Pokémon level is not directly displayed. Implement a level-calculation engine.

Inputs:

- Species
- Form
- CP
- Attack IV
- Defense IV
- Stamina IV
- Species base Attack
- Species base Defense
- Species base Stamina
- CP multiplier table

Evaluate supported half-level increments and calculate CP using the Pokémon GO CP formula.

Return:

- Exact level when uniquely determined
- A list of possible levels when ambiguous
- A confidence value
- A validation error when no level matches

Keep species data and CP multiplier data in local versioned JSON assets or database tables. Design an update mechanism so game-data tables can be replaced later.

## Duplicate and stop detection

Do not assume that two Pokémon with the same species, CP, and IVs are necessarily the same Pokémon.

Build a fingerprint using a combination of:

- Species
- CP
- IVs
- Level
- Favorite status
- Visible nickname
- Perceptual hash of sprite or screen region
- Previous and next scan sequence context
- Session position

Experimental automatic scanning should stop when one or more of these conditions occur:

- The first sequence of Pokémon fingerprints repeats.
- The same Pokémon is detected repeatedly after several swipe attempts.
- The Pokémon screen is no longer detected.
- A configured maximum scan count is reached.
- Screen capture permission ends.
- Pokémon GO leaves the expected screen.
- The user presses Stop.
- An unrecoverable recognition error occurs.
- The accessibility service cannot advance.
- The screen sequence begins repeating.

Use conservative stop logic to avoid infinite loops.
